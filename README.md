# 매트리스 KPI 시스템

FURSYS · iloom 매트리스 **생산팀·품질보증팀 KPI 통합 콘솔**.

매일의 생산 KPI와 봉탈(부적합) 기록을 입력하고, ERP 부적합 리포트를 올리면
대시보드에서 일·주·월 추세를 한 화면으로 봅니다. 입력한 내용은 모든 PC에 자동으로 공유됩니다.

- **사용 방법** — 이 문서
- **구조·설계** — [ARCHITECTURE.md](ARCHITECTURE.md)

## 1. 시작하기

### 브라우저로 접속

사내 서버 주소를 브라우저에 입력하면 바로 쓸 수 있습니다. 설치할 것은 없습니다.

> 운영 서버 주소는 팀 내부 공지를 참고하세요.

### 내 PC에서 직접 띄우기

Python이 설치돼 있어야 합니다.

```
실행.bat 더블클릭
```

패키지를 설치하고 서버를 띄운 뒤 `http://localhost:8000` 으로 접속하면 됩니다.
`.env` 파일에 DB 접속 정보(`DATABASE_URL`)가 있어야 동작합니다 ([11. 운영자용](#11-운영자용) 참고).

> **다른 PC에서 `http://<서버IP>:8000`으로 접속할 때** — 대부분의 기능은 그대로 동작하지만,
> 브라우저 보안 정책 때문에 **Gemini API 키 비밀번호 설정·해제만 막힙니다.**
> 전 기능을 쓰려면 HTTPS 주소로 접속해야 합니다.

### 처음 접속하면

상단 바 오른쪽에 초록 점과 **"동기화"** 표시가 뜨면 서버와 연결된 상태입니다.
30초마다 자동으로 다른 PC의 변경 사항을 받아옵니다.

## 2. 화면 구성

홈 화면에 카드 3개가 있습니다.

| 카드 | 하는 일 |
|------|--------|
| **대시보드** | 생산 6개 KPI + 품질 지표를 기간별로 조회 |
| **생산팀** | 일간 KPI·봉탈 기록 입력, 주간 기록, 종합 지표 |
| **품질보증팀** | ERP 부적합 리포트 업로드, 종합 지표, 외주협력업체 |

상단 바에서 **홈**으로 돌아가거나, 생산팀 ↔ 품질보증팀을 오가거나, **목표 설정** 화면으로 들어갑니다.
오른쪽 끝에는 동기화 상태와 마지막 동기화 시각이 표시됩니다.

## 3. 생산팀 — 일간 KPI 입력

생산팀 → **일간 입력** 탭.

1. 오른쪽 위 **입력 일자**에서 날짜를 고릅니다 (기본값은 어제).
2. 공정별 표에 값을 채웁니다.

   | 공정 | 과제 1 | 과제 2 | 과제 3 |
   |------|--------|--------|--------|
   | **발포** | 스펀지 수율 (레코텍/엘라스틱/테롤) | 외주 폼 내작 진행률 | 현장 지원 능력 |
   | **퀼팅** | 봉탈률 (퀼팅 + 인터로크) | 치수 불량률 | 현장 지원 (퀼팅 + 인터로크) |
   | **스프링** | 일 평균 생산량 (1·2라인) | 품목 교체 시간 (1·2라인) | 현장 지원 능력 |

3. 오른쪽 위 **신규 저장** / **수정 저장** 버튼을 누릅니다.

### 알아두면 좋은 것

- **금주 진행 예정**과 **현장 지원 능력**은 같은 주의 다른 날짜에 적어둔 값이 자동으로 따라옵니다.
  매일 다시 쓸 필요가 없고, 그 날만 다르면 덮어쓰면 됩니다.
- **퀼팅 봉탈률은 직접 안 채워도 됩니다.** 봉탈 기록을 저장하면 그 날짜의 봉탈률이 자동 계산돼 들어갑니다
  ([4. 봉탈 기록](#4-생산팀--봉탈-기록-입력) 참고).
- 저장하기 전에 다른 탭으로 옮겨도 입력값은 남아 있습니다.

## 4. 생산팀 — 봉탈 기록 입력

생산팀 → **봉탈 기록** 탭. 작업일지의 **생산량 표**와 **부적합 표**를 그대로 옮겨 담는 화면입니다.

### 4-1. 먼저 일자와 작업자를 고릅니다

상단의 **입력 일자**와 **작업자**를 맞춥니다. 이 둘이 한 건의 작업일지를 구분하는 기준입니다.
같은 일자·작업자로 이미 저장한 기록이 있으면 자동으로 불러와 이어서 수정할 수 있고,
**"등록됨 · N건"** 초록 배지로 표시됩니다.

작업자 목록을 고치려면 작업자 옆 **✎** 버튼을 누르고 콤마로 구분해 입력합니다.

### 4-2. 사진으로 자동 입력 (권장)

1. 작업일지를 찍은 사진을 **Ctrl+V로 붙여넣거나**, 사진 영역을 클릭해 파일을 고릅니다.
2. **자동 인식** 버튼을 누릅니다. 사진은 자동으로 압축돼 올라갑니다.
3. 생산량 표와 부적합 표가 채워지면 **설비(작업자)를 선택**합니다.
4. 사진의 날짜가 화면 날짜와 다르면 바꿀지 물어봅니다.
5. **잘못 읽은 곳을 직접 고친 뒤 저장하세요.** 고친 내용은 학습돼 다음 인식이 더 정확해집니다.

> **신제품이 나와도 따로 등록할 필요 없습니다.** 새 품목이나 새 불량 원인은 처음 두 번만
> 손으로 고쳐 저장하면, 세 번째부터 자동으로 인식됩니다. 저장된 작업일지에서 2회 이상
> 쓰인 값이 인식 사전에 자동으로 편입되기 때문입니다. 자동완성 목록에도 함께 나타납니다.

> 자동 인식에는 Gemini API 키가 필요합니다. 키가 없으면 사진 영역 위 버튼이 빨갛게 표시됩니다.
> 키는 팀이 공유하며, 등록·변경에는 비밀번호가 필요합니다.

### 4-3. 수기로 입력

표에 직접 입력해도 됩니다.

- **마지막 행에 뭔가 입력하면 빈 행이 자동으로 하나 더 생깁니다.** "+ 행 추가"를 누를 필요가 없습니다.
- 필요하면 **+ 행 추가** 버튼으로 직접 추가하고, 행 오른쪽 **×**로 지웁니다.
- **빨간 점선 테두리**는 아직 안 채운 칸이라는 뜻입니다.
- **노란 배경 행**은 위 행과 내용이 완전히 같다는 뜻입니다. 사진에 실제로 두 줄이 있는지
  확인하세요 — 사진 인식이 같은 줄을 두 번 만드는 경우가 있습니다.
- 품목·사이즈·원인·원인공정·처리내역 칸은 입력하면 자동완성 목록이 뜹니다.
- 맨 아래 빈 행은 저장할 때 알아서 빠지므로 지우지 않아도 됩니다.

### 4-4. 저장

**저장** 버튼을 누르면:

- 그 일자·작업자의 작업일지로 저장되고, 아래 **등록된 작업일지** 이력에 나타납니다.
- 그 날짜의 **퀼팅 봉탈률·인터로크 봉탈률이 자동 계산**돼 일간 KPI에 반영됩니다.
  (원인이 `봉탈`인 건만 계산에 들어가고, 그 날 전체 생산량으로 나눕니다)
- 사진 인식 결과를 고쳤다면 그 교정 내용이 학습 기록에 쌓입니다.

작업자를 바꿔가며 여러 건을 연달아 입력할 수 있습니다. 저장 후 작업자만 바꾸면 빈 표가 새로 뜹니다.

### 4-5. 저장한 기록 다루기

화면 아래 **등록된 작업일지** 표에서:

- **수정** — 입력 화면으로 불러옵니다.
- **삭제** — 그 작업일지와 부적합 기록을 함께 지웁니다.
- **CSV 다운로드** — Excel에서 한글이 깨지지 않게 내려받습니다.

## 5. 생산팀 — 나머지 탭

| 탭 | 하는 일 |
|----|--------|
| **주간 기록** | 담당자별 주간 성장 로그. 칸을 벗어나면 자동 저장됩니다 |
| **종합 지표** | 일별·주별·월별·기간·전체 추세 |
| **봉탈 분석** | 봉탈률 추세, 원인·품목·작업자별 Top, 품목 불량률 |
| **작성 이력** | 저장된 일간 KPI 목록. 지운 항목은 휴지통에 **7일** 보관 후 자동 삭제 |

> 봉탈 분석의 **품목 불량률**은 봉탈 기록의 **생산량 표**가 있어야 계산됩니다.
> "생산 데이터 없음"이 보이면 생산량 표를 먼저 채워주세요.

## 6. 품질보증팀 — ERP 부적합 리포트

품질보증팀 → **부적합 리포트** 탭.

1. ERP에서 받은 `grd_list_*.xls` 파일을 점선 영역에 **끌어다 놓거나 클릭해서 선택**합니다.
2. 자동으로 파싱돼 발생일별 리포트로 저장됩니다.

### 자동으로 걸러지는 것

- **품목명에 "커버"가 없는 행은 제외**됩니다.
- 부적합 유형은 7종으로 정리됩니다 — 퀼팅 봉탈 · 인터 봉탈 · 작업자 부주의 · 오염 및 얼룩 ·
  구멍 및 찢어짐 · 이물 · 기타
- 원인공정에 따라 층이 나뉩니다 — 커버 퀼팅·인터로크는 4층, 외주협력업체는 별도, 나머지는 2층
- 처리결정에 폐기·파기·스크랩·반품·반납이 있으면 **폐기**, 그 외는 **수리**로 분류됩니다

### ⚠️ 재업로드 시 주의

**같은 발생일의 기존 리포트는 파일명과 무관하게 통째로 대체됩니다.**
그 날짜에 직접 입력해 둔 *공정 이상발생·투입 수량·비고*도 함께 사라지니,
같은 날짜를 다시 올릴 때는 미리 확인하세요.

### 직접 수정하기

*공정 이상발생·투입 수량·비고* 칸은 **하루치만 보고 있을 때** 클릭해서 고칠 수 있습니다.
주별·월별처럼 여러 날을 합쳐 보는 중에는 수정되지 않습니다.

손실비용은 **폐기 / 수리 / 합계** 세 열로 나뉘며, 각 칸을 누르면 해당 원본 내역이 펼쳐집니다.

### 나머지 탭

| 탭 | 하는 일 |
|----|--------|
| **종합 지표** | 기간별 부적합 건수·손실 추세 |
| **외주협력업체 관리** | 업체별 부적합·손실 집계 |
| **업로드 이력** | 올린 파일 목록. 지운 항목은 휴지통에 **7일** 보관 |

## 7. 대시보드 보기

홈 → **대시보드**.

- 위쪽 **기간 토글**로 일별(기본, 어제) / 주별 / 월별 / 전체를 고릅니다.
- **생산 KPI 6장** — 각 카드에 목표 대비 상태와 직전 대비 증감(△/▼)이 표시됩니다.
- **공정별 상세** — 발포·퀼팅·스프링을 행 단위로 비교합니다.
- **품질 KPI 3장** — 발생 건수·내부 손실·외주 손실, 그리고 유형 도넛과 공정 막대.

카드 색(초록·노랑·빨강)은 [목표 설정](#8-목표임계값-설정)에서 정한 기준을 따릅니다.

## 8. 목표·임계값 설정

상단 바의 **목표 설정** 버튼으로 들어갑니다.

- **생산팀 목표** — 6개 KPI마다 `목표 / 주의 / 위험` 값을 정합니다.
- **품질팀 목표** — 부적합 건수 2항목 + 손실 금액 4항목의 월 누적 상한을 정합니다.

여기서 정한 값이 대시보드 카드 색과 경고 표시의 기준이 됩니다.

## 9. 입력이 사라지지 않게 하는 장치

입력 중에 값이 사라지지 않도록 아래가 동작합니다. 따로 조작할 것은 없습니다.

| 장치 | 동작 |
|------|------|
| **자동 임시저장** | 봉탈 기록은 입력할 때마다 이 PC에 임시 보관됩니다. 탭을 옮기거나 실수로 새로고침해도 돌아오면 **"저장하지 않은 입력을 복원했습니다"** 안내와 함께 복구됩니다 (3일간 보관) |
| **이탈 경고** | 저장 안 한 입력이 있는 상태로 창을 닫거나 새로고침하면 브라우저가 한 번 물어봅니다 |
| **동기화 보호** | 입력하는 중에는 30초 자동 동기화가 화면의 표를 건드리지 않습니다 |
| **저장 실패 보관** | 서버 저장에 실패해도 값은 이 PC에 남고, 20초마다 자동으로 다시 시도합니다 |

그래도 다음 두 경우에는 입력이 초기화되니 주의하세요.

- **일자나 작업자를 직접 바꿨을 때** — 그 일자·작업자의 저장본을 새로 불러옵니다.
- **이력에서 다른 작업일지의 "수정"을 눌렀을 때**

## 10. 자주 겪는 상황

### 상단에 빨간 점과 "저장 대기 · N건 재시도"가 보입니다

서버 저장에 실패한 항목이 있다는 뜻입니다. **값은 이 PC에 남아 있습니다.**
20초마다 자동 재시도하고, 숫자를 누르면 즉시 다시 시도합니다.
계속 빨간 상태라면 서버나 네트워크 문제이므로 운영 담당자에게 알려주세요.
**이 상태에서는 브라우저를 닫지 마세요.**

### 다른 PC에서 저장한 내용이 안 보입니다

동기화는 30초 주기입니다. 잠시 기다리거나 새로고침하세요.
단, **내가 입력하는 중인 표는 일부러 갱신하지 않습니다.** 저장한 뒤에 반영됩니다.

### 입력하던 값이 사라졌습니다

일자·작업자를 바꾸지 않았는데도 사라진다면 알려주세요.
사라진 직후라면 같은 일자·작업자로 돌아가면 임시저장본이 복원될 수 있습니다.

### 비밀번호 설정이 안 되고 안내 문구가 뜹니다

`http://<서버IP>:8000` 처럼 HTTPS가 아닌 주소로 접속했을 때 나타납니다.
브라우저가 암호 기능을 막기 때문이며, `https://` 또는 `localhost` 주소로 접속하면 됩니다.
다른 기능은 그대로 쓸 수 있습니다.

### 사진 인식이 실패합니다

| 메시지 | 조치 |
|--------|------|
| API 키가 잘못됐거나 이미지 형식이 지원되지 않습니다 | 키를 다시 확인하세요 |
| API 키 권한이 없습니다 | 키 발급 설정을 확인하세요 |
| 요청 한도를 초과했습니다 | 잠시 후 다시 시도하세요 |
| Gemini 서버 오류 | 잠시 후 다시 시도하세요 |
| 사진이 너무 흐리거나 글씨가 잘 안 보이면… | 밝은 곳에서 다시 촬영하세요 |

인식이 계속 부정확하면 수기로 고쳐 저장해 주세요. 고친 내용이 학습됩니다.

### 인식이 엉뚱한 값으로 계속 틀립니다

사진 영역 위의 **"학습 N건"** 버튼을 눌러 학습 데이터를 초기화해 보세요.
고친 내용이 잘못 쌓이면 오히려 인식을 방해할 수 있습니다. 초기화해도 작업일지 기록은
그대로 남고, 앞으로의 수정 내용만 다시 쌓입니다.

### 첫 화면이 뜨는 데 몇 초 걸립니다

화면 코드를 브라우저가 매번 변환하는 구조라 첫 로드가 느립니다.
두 번째부터는 캐시되어 빨라집니다.

### 봉탈 분석에 "생산 데이터 없음"이 보입니다

봉탈 기록의 **생산량 표**가 비어 있습니다. 생산량을 입력하면 불량률이 계산됩니다.

## 11. 운영자용

### 실행에 필요한 것

`.env` 파일에 DB 접속 문자열이 있어야 합니다 (`.env.example` 참고).

```
DATABASE_URL=postgresql://postgres:<비밀번호>@db.<project-ref>.supabase.co:5432/postgres
```

`sslmode`가 없으면 자동으로 `require`가 붙습니다.
테이블(`kpidb`)은 서버 기동 시 자동 생성됩니다.

### 로컬 실행

```
실행.bat
```

또는

```bash
pip install -r requirements.txt
uvicorn app:app --host 0.0.0.0 --port 8000
```

### 컨테이너 배포

```bash
docker build -t kpi-dashboard .
docker run -d -p 8000:8000 -e DATABASE_URL="postgresql://..." kpi-dashboard
```

`.env`는 이미지에 포함되지 않으므로 **환경변수로 주입**해야 합니다.
`index.html`을 갱신한 뒤에는 브라우저 강제 새로고침(Ctrl+F5)이 필요할 수 있습니다.

### 백업

모든 데이터가 `kpidb` 테이블 한 곳에 있습니다.

```sql
SELECT env, key, value, updated_at FROM kpidb;
```

각 PC의 localStorage에도 같은 값이 남아 있어, DB 장애 시에도 마지막으로 접속한 PC에서는 화면이 뜹니다.

### ⚠️ 접근 제어가 없습니다

`/api/data`에는 인증이 없어, 서버에 접근할 수 있는 누구나 전체 데이터를 읽고 덮어쓸 수 있습니다.
여기에는 **Gemini API 키(평문)** 와 작업자 이름이 포함됩니다.
사내망 전용이라는 전제에서만 안전하며, 공개 주소로 운영한다면 리버스 프록시 인증이나
네트워크 차단이 필요합니다. 자세한 내용은 [ARCHITECTURE.md](ARCHITECTURE.md)의 *10. 접근 제어*를 보세요.

### 저장소에 올리면 안 되는 것

`.gitignore`로 제외돼 있습니다 — `.env`, `실행.bat`, 일회성 마이그레이션 스크립트,
`grd_list_*.xls`(실 ERP 데이터), `node_modules/`, `__pycache__/`.
